# ADR 056: 🤝 営業・名刺管理 — 名刺を全員で共有し、メールは「本人の Gmail」から確認して送る

- Status: Accepted
- Date: 2026-11-14
- Decided by: さとるさん（2026-11-14 のスレッドで 4 点を選択）
- Related: ADR 015（VIEW AS チェックリスト）, ADR 032 / 036（本人専用データの前例）, ADR 039（AI の月次予算ガード）, ADR 048（新テーブルは RLS 必須）

## Context

HARUKA FILM として「案件が今どう動いているか」を、受注前（営業・商談中）から見える化したい。あわせて名刺管理も HFS に持ちたい。

想定する使い方（さとるさん 2026-11-14）:

1. 交流会で出会い、名刺を交換する
2. 名刺をスクリーンショット（写真）で取り込み、名前・住所・会社名・事業内容を読み取る
3. いつ・どこで・誰と出会ったかを記録する。自分だけのメモも残す
4. その内容をもとにメールを送る。HARUKA FILM のプロモーション動画を何本もまとめた URL を付ける
5. 画面はメンバー全員が見られる。ただしメール送信は作った本人（または本人が認めた代理）だけ。誤送信を防ぐ

既存の HFS には受注後の `clients` / `projects` しか無く、受注前の相手を置く場所が無い。メール送信の仕組みも無い。

## Decision

### 1. 連絡先 1 行に「営業の進み具合」を持つ（商談テーブルは分けない）

`sales_contacts` = 名刺 1 枚。同じ行に `stage` を持ち、画面は stage ごとの列（かんばん）で見せる。

| stage | 表示 | 意味 |
|---|---|---|
| `met` | 🤝 出会い | 名刺交換しただけ |
| `approach` | ✉ アプローチ中 | メール・連絡を始めた |
| `negotiating` | 💬 商談中 | 打ち合わせをしている |
| `proposal` | 📄 提案・見積 | 提案や見積を出した |
| `won` | 🎉 受注 | 受注。`client_id` で既存クライアントに紐づけられる |
| `lost` | 失注 | |
| `hold` | 保留 | |

- 最初のメールを送ると `met` → `approach` へ自動で進める（それ以外は手で動かす）
- 受注後の制作は従来どおり `clients` / `projects` で管理する。こちらは受注「前」の台帳

### 2. 見るのは全員。直せるのは担当と管理者。個人用メモは本人だけ

- 閲覧: ログイン中の全員（権限キーは作らない）
- 連絡先の編集・進み具合の変更・アーカイブ: 担当（`owner_user_id`＝登録した人）と管理者（実効ロール）
- 個人用メモ（`sales_contact_private_notes`）: 書いた本人だけ。**管理者にも VIEW AS でも見せない**（`req.user.id` で判定。ADR 032 と同じ）
- 名刺画像は一覧に載せず、詳細を開いたときだけ別 API で返す（base64 を一覧 select に含めない）

### 3. メールは「差出人本人の Gmail」から送る。送れるのは本人か、本人が認めた代理だけ

- 各メンバーが HFS に Google 連携（`gmail.send` 権限だけ。受信箱は読めない）。トークンは既存の `user_oauth_tokens` に `scope_key='gmail.send'` で保存
- 返信は本人の受信箱に届き、Gmail の送信済みにも残る。追加費用なし
- `sales_mails.sender_user_id` = 差出人（この人の Gmail から出る）
- 下書きを作れる・直せる・送れるのは **差出人本人** か **差出人が代理に認めた人**（`sales_mail_delegates`）だけ
  - 判定は必ず `req.user.id`（本当のログイン本人）。**管理者でも他人の名前では送れない。VIEW AS 中は送信不可**
  - 代理の許可・取り消しは差出人本人だけができる
- 誤送信を防ぐ仕組み
  - 自動送信はしない。AI は下書きまで。人が宛先・件名・本文を見て送信ボタンを押す
  - 送信 API は「画面で確認した宛先」を一緒に受け取り、下書きの宛先と一致しなければ送らない
  - `status` を `draft → sending` へ条件付き更新できた 1 回だけが送る（連打・二重タブでも 1 通）
  - 1 通 = 宛先 1 件（CC・BCC・一斉配信なし）。差出人ごとに 1 日 50 通まで
  - `do_not_email` の相手には送れない
- 特定電子メール法への配慮: 名刺交換した相手は同意の例外にあたるが、本文末尾に差出人の氏名・会社名と「ご案内が不要な場合はご返信ください」を必ず付ける

### 4. プロモ動画は YouTube / Vimeo の URL を登録し、紹介ページ（/pv/<token>）にまとめる

- `sales_promo_videos` = 動画ライブラリ（タイトル・URL）。登録・編集は全員
- `sales_promo_pages` = メールごとに発行する紹介ページ。推測できない token の URL、ログイン不要
- ページは HFS がサーバー側で組み立てる HTML。動画は YouTube / Vimeo の埋め込みなので HFS の回線を使わない
- 開かれた回数・初回日時を記録し、連絡先の画面に「👀 開封済み」を出す
- 検索エンジンに載せない（`noindex`）。発行した本人と管理者が公開を止められる
- HFS の納品作品（Drive 上のクライアント作品）は出さない。社外公開の許諾管理が要るため次段階

### 5. AI（名刺読み取り・メール下書き）は専用フラグと月の上限額で止める

- 既存の Vertex AI Gemini を使う（1 枚あたり 1 円未満の見込み）
- `ENABLE_SALES_AI=true` のときだけ動く。キーの有無では判定しない
- `SALES_AI_MONTHLY_BUDGET_JPY`（既定 500 円）を `sales_ai_usage` の当月合計（JST）が超えたら止め、手入力・テンプレ文面に切り替える
- 名刺読み取りの結果は入力欄に入れるだけで、人が直してから保存する

## Consequences

- 受注前の相手と進み具合が 1 画面で見える。名刺は全員の資産になる
- メールは本人のアドレスから出るので、なりすましや共有アドレスの取り違えが起きない
- Google の同意画面に `gmail.send` の追加が必要（さとるさん作業）。審査前は「未確認のアプリ」の警告が出る
- 1 連絡先 = 1 商談なので、同じ相手との 2 回目の商談は進み具合を戻して使う。件数が増えたら商談テーブルを分ける
- 一斉配信・予約送信・返信の取り込み・開封通知は入れていない（次段階）

## Alternatives considered

- **会社の共通アドレスから配信サービスで送る**: 配信サービスの契約・ドメイン設定が要る。返信が共通の受信箱に集まり「本人しか送れない」と相性が悪い → 不採用
- **名刺登録と同時に自動送信**: AI の読み間違い（宛先・社名・氏名）がそのまま相手に届く → 不採用
- **HFS の納品作品を紹介ページに出す**: クライアント作品の社外公開になる。Drive 経由の再生も遅い → 次段階
- **連絡先と商談を別テーブル**: 正しいが初版には重い。使われ方を見てから分ける
