# ADR 046: 請求書テンプレ（スプレッドシート）へ納品済み分を下書き出力

- Status: Accepted
- Date: 2026-09-28
- 関連: ADR 026（納品完了日で請求月判定）/ ADR 034（初稿請求 billing_timing）/ 振込管理（#1099）

## 背景

法人化（2026-09-22 設立）に合わせ、さとるさんが新しい請求書テンプレ
「【株式会社HARUKA FILM】請求書テンプレート」（Sheets, id `1VuKNpoqTkmczbvSP3oTLL-LXcE6Z0fvgQbbTPj7hfm8`）を作成した。
税抜単価・発行者区分（個人／法人）・明細ごとの源泉区分に対応した書式。

メンバーは毎月このテンプレを複製して手入力 → PDF を請求書フォルダへ提出している。
手入力のため **二重請求・請求漏れ・案件取り違え** が毎月発生している。
HFS には納品実績があるので、それを下書きとして流し込めば入力の大半が不要になる。

## 決定

HFS から「当月の納品済み分を書き込んだテンプレのコピー」を本人の請求書フォルダに作る。
本人はそれを開き、**単価の入力と、HFS に載らない分（LP一式・時給・立替など）の追記**だけ行って PDF 提出する。

### 流し込む／流し込まないもの

| 項目 | 扱い |
|---|---|
| 納品日・区分(HF/GND)・案件名・品目・内訳・数量・単位 | HFS から自動入力 |
| **税抜単価** | **取り込まない（空欄）**。2026-09-28 さとるさん判断。HFS の単価は税込/税抜の前提が混在しうるため、本人入力を正とする |
| **源泉区分** | **既定「対象」**。2026-09-28 のルール決定。対象外の業務だけ本人が変更 |
| 発行者区分（個人／法人） | 空欄（本人が選択）。法人メンバーに源泉が誤適用されるのを防ぐため既定値を入れない |
| 発行者名・住所・TEL・登録番号・振込先 | users の登録情報から自動入力（未登録は空欄） |
| 請求対象期間・件名・請求日 | 対象月から自動（請求日=月末、支払期限=翌月末） |

### 明細のまとめ方

テンプレの明細は 4 行 1 枠で 1 人あたり月数十本になるため、**1 クリエイティブ = 1 枠にはしない**。
`区分 × 案件 × 役割（編集/デザイン/ディレクション等）× 種別（動画/静止画）` で 1 枠にまとめ、
数量 = 本数、内訳 = クリエイティブ名の一覧とする。枠が足りなければ枠を増やし、合計系の数式範囲を書き直す。
（単価が同じ案件内で異なる場合は本人が枠を分ける）

### 対象クリエイティブ

請求書プレビュー（`/invoices/preview-items`）と同じ請求月判定（ADR 026 / 034）で当月に入るもののうち、
**実際に納品完了（on_first_draft 案件は初稿提出済み）しているものだけ**。締切が当月なだけの未納品は載せない。

### 二重請求への備え

各枠に対応するクリエイティブ ID を非表示の列と非表示シート `_hfs` に残す。
請求月は納品日で一意に決まるので、HFS 由来の行が月をまたいで重複することはない。
将来、提出 PDF／シートと突き合わせて「同じクリエイティブを2か月で請求」を検知する時の手がかりにする（本 ADR の範囲外）。

### 置き場所・再作成

- 本人の「氏名 YYYY年MM月」請求書フォルダ（無ければ既存の請求書フォルダ生成ロジックで作成）。
- 同名ファイルが既にあれば新規作成せずそのリンクを返す（本人の追記を上書きしない）。作り直しは明示操作のみ。
- テンプレ ID は `system_settings.invoice_sheet_template_id`（未設定なら上記 ID）。migration 不要。

## 却下した案

- **HFS 内蔵の請求書作成（invoices/generate）へ全面移行**: 機能は既にあるが、運用は PDF 提出で定着しており、税抜・源泉区分の新書式にも未対応。メンバーの手順変更コストが大きい。
- **単価も HFS から入れる**: 上記のとおり、単価の正を本人入力に置く判断。

## 影響

- 外部 API 費用なし（Drive / Sheets API は無料枠内）。
- 振込管理の Drive スキャンは PDF のみ対象のため、同じフォルダにスプレッドシートが増えても誤検知しない（実装時に確認）。

## 実装メモ（2026-09-28）

- API: `POST /api/haruka/invoices/draft-sheet`（body `{ year, month, force? }`・本人固定・`invoice_folder.generate_own`）。
  書き込みは読み取り 2 回＋`spreadsheets.batchUpdate` 1 回。純関数は `utils/invoice-sheet-draft.js`。
- 対象の候補収集は `/invoices/preview-items` から `collectInvoiceCandidateCreatives` として切り出して共有（preview-items の挙動は変えていない）。
  下書き側だけで次を追加で除外する: 未納品（on_first_draft は初稿未提出）／自分の役割が Wチェック担当（`wcheck`）だけの分／
  `is_payable=false` かつ `special_payable` でない分（on_first_draft 案件は納品前に計上するので除外しない）。
  役割は自分の `creative_assignments.role`（editor・director_as_editor=編集、designer=デザイン、director=ディレクション、producer=プロデュース）と、
  納品時スナップショット優先の案件 D / P（ADR 009）。1 本に複数役割があればそれぞれの枠に入る。
- 区分は `clients.billing_org`（gnd→GND / haruka→HF / 未設定→空欄のまま本人が選ぶ）。
- テンプレの枠（18〜49 行・8 枠）を超えたら 49 行の後ろに 4 行ずつ挿入し、最終枠から書式・結合・入力規則・数式をコピー。
  H14 / A15 / K52〜K57（C53・E53 含む）の数式と源泉区分の条件付き書式の範囲を、全枠を含むように書き直す。
- マスタ（案件名プルダウンの参照先）はテンプレ既存の名前＋今回の案件名＋進行中案件名。59 件を超えたら案件名セルの入力規則の範囲を広げる。
- 振込管理の Drive スキャンは Google ネイティブ形式（スプレッドシート等）を対象外にしているため影響なし（確認済み）。
  一方、請求書フォルダの「提出済み（緑）」判定 `checkFolderHasFiles` は全ファイルを数えていたため、スプレッドシートを数えないよう変更した
  （下書きを作っただけで提出済み表示になるのを防ぐ）。
