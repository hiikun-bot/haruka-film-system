# ADR 044: つぶやきのリアクションは「基本 5 種 ＋ 『＋』で開く拡張パレット」

- Status: Accepted
- Date: 2026-09-25
- Related: ADR 042（作品ギャラリーのリアクション・`utils/reactions.js` への定義集約）, ADR 041（つぶやきの新着は割り込まず気配で気づかせる）, 通知 Phase 1 段階4（`2026-05-03_notification_phase4_tweets_rich.sql`）, 返信へのリアクション（#1173 / #1174）

## Context

つぶやき（本体・返信）のリアクションは 👍 ❤️ 👏 😊 😳 の 5 種固定で、ピッカー（➕）を開いてもこの 5 つしか選べない。
「基本スタンプに＋ボタンを置いて、爆笑（🤣）などいろんな絵文字をリアクションとして選べるようにしたい」という要望があった（2026-09-25）。

現状の確認結果:

| 項目 | 実装状況 |
|---|---|
| 種類の定義 | `utils/reactions.js` の `REACTIONS`（5 種）。サーバー（API の許可判定・通知の絵文字）とフロント（ピッカー・ピル）が同じ配列を読む（ADR 042） |
| DB | `tweet_reactions` / `tweet_comment_reactions` の `reaction_type` に **列挙 CHECK**（`IN ('good','heart','clap','smile','surprised')`）。`portfolio_reactions` には CHECK 無し（許可値はコード側） |
| 通知 | `post_reaction` 通知の文面と 24h 集約（`routes/notifications.js`）が type → 絵文字の表を持つ |
| 作品ギャラリー | 同じ 5 種を「ナイス！／好き／参考になる／ほっこり／すごい…！」の言葉つきで出す（ADR 042 追補） |

社内 SNS としての「押す理由」を増やしたい一方で、Slack のような全部入りの絵文字ピッカー（数千種・検索・スキントーン）は、
ピッカーが重くなる・ピルの並びがばらける・通知の文面で絵文字が説明できない、と失うものも多い。

## Decision

### 1. ピッカーは「基本 5 種の行 ＋ 『＋』」。『＋』で拡張パレット（グリッド）が同じ吹き出しの中に開く

```
[👍][❤️][👏][😊][😳] [＋]        ← 従来どおりワンクリックで押せる
──────────────────────────
[🤣][😂][😭][😍][🤩][🥰][😅][🤔]  ← 「＋」で開く。8 列（スマホ 6 列）・5 行を超えたらスクロール
[😎][😱][🤯][🥺][🥳][🤗][😉][😋]
[😢][😴][😇][🙈][🙌][🙏][💪][👌]
[✌️][🤝][👀][🙇][👋][🔥][🎉][💯]
[✨][🚀][🏆][🎬][💡][☕][🍺][🎂]
[💐][🍀][💦][💤]
```

- 基本 5 種の位置・順番・ワンクリック性は変えない（慣れた指の動きを壊さない）。
- 「＋」は絵文字ボタンと見分けがつくよう点線の丸。押すと `−` に変わり、もう一度押すと閉じる。
- 自分が押している種別は基本行・パレットとも強調（`.active`）。もう一度押すと外れる（トグル運用は従来どおり）。
- 吹き出しが画面右端からはみ出すときは、はみ出したぶんだけ左へずらす（`_twFitPicker`。左端 8px は割らない）。

### 2. 拡張パレットは「厳選した約 40 種」を `utils/reactions.js` の `EXTRA_REACTIONS` に持つ。全部入りピッカーは入れない

- 顔 → 手 → もの の順。社内 SNS で「押す理由」が立つもの（爆笑・号泣・アツい・おめでとう・おつかれさま・かんぱい…）に絞る。
- 端末差で豆腐（□）にならないよう Emoji 11（2018）までに限定する。
- 各種別に短い `label`（爆笑／アツい／おつかれさま…）を持ち、ホバーの吹き出し・title に出す。通知の文面にも絵文字を使う。
- 足すときは `EXTRA_REACTIONS` に 1 行足すだけ。**一度使った `type` は変えない**（DB に文字列で残る。絵文字・label の差し替えは可）。

### 3. DB は列挙 CHECK をやめ、形式 CHECK（`^[a-z][a-z0-9_]{0,31}$`）だけにする。許可値はコード側が正

- `portfolio_reactions`（ADR 042）と同じ流儀に揃える。絵文字を 1 つ足すたびに migration を書かなくてよい。
- migration `2026-09-25_tweet_reactions_relax_type_check.sql`：制約名に依存せず `reaction_type` を参照する CHECK を全部落とし、固定名の形式 CHECK を付け直す（冪等）。
- API（`POST /tweets/:id/reactions` と返信側）は `ALL_REACTION_TYPES` で許可判定する。migration 未適用の DB で拡張種別を入れて `23514`（check_violation）になったときは 500 ではなく 400 で「この絵文字はまだ使えません（システム更新待ち）」を返し、基本 5 種は従来どおり通る。

### 4. 拡張パレットはつぶやき（本体・返信）だけ。作品ギャラリーには（今は）出さない

- 作品ギャラリーは「作品を褒める言葉つきの 5 種」（ADR 042 追補）が設計意図で、🤣 や 😴 が並ぶと褒め言葉の場が崩れる。
- `REACTIONS` / `REACTION_TYPES` / `PORTFOLIO_*` は基本 5 種のまま不変。`utils/portfolio-reactions.js` の許可判定も 5 種のまま。
- 作品側にも欲しくなったら `PORTFOLIO_EXTRA`（褒め言葉になるものだけ 🔥 🏆 🎬 …を選抜）を別途定義する（別 ADR または追補）。

### 5. サマリのピル（押された種別の一覧）は「基本 5 種 → 拡張パレット順」で並べ、定義に無い種別も隠さない

- 並びが端末・人によって変わらないよう定義順で固定。
- 古いタブが新しい種別（将来の追加分）を受け取ったときは ✨ で末尾に出し、件数を消さない。

## Consequences

- つぶやき・返信のピッカーに「＋」が付き、🤣 などを 2 クリックで押せる。押した種別はピルに並び、もう一度押すと外れる。
- `utils/reactions.js` に `EXTRA_REACTIONS` / `ALL_REACTIONS` / `ALL_REACTION_TYPES` / `isBaseReactionType` が増える。`REACTION_EMOJI` / `REACTION_LABEL` は基本＋拡張の全部を引ける（通知の文面はこれを使う。`routes/notifications.js` の独自表は撤去）。
- Stage 分割: migration（#1195）を先に本番適用してからコード PR をマージする。順序が逆になっても基本 5 種は壊れず、拡張種別だけ 400 の分かる文言になる。
- 1 つのつぶやきに多種類のピルが並び得る（最大 49 種）。`.tweet-reaction-summary` は折り返し表示のまま。件数集計・楽観的更新（`_twApplyReactionLocal`）は種別に依存しないので変更なし。

トレードオフ:
- 「全部の絵文字から選びたい」には応えていない（意図的）。要望が続くなら検索付きピッカーを別 ADR で。
- 拡張パレットは 2 クリック。基本 5 種に何を置くかは変えていないので、🤣 が基本行に欲しいという声が出たら並び替えを検討する。

## Alternatives considered

1. **全部入り絵文字ピッカー（ライブラリ導入）** — 外部 CDN 依存は iPhone Safari の Script error 事故（PR #1166/#1169 で CDN ゼロ化）に逆行する。自オリジン同梱でも数百 KB が増え、ピルの並び・通知の文面・集計に「任意の文字列」が入るため見送り。
2. **`reaction_type` に絵文字そのものを保存する** — 定義表が要らなくなるが、異体字セレクタ（❤️ と ❤）やスキントーンで同じ意味の行が分かれ、UNIQUE が効かなくなる。type コードのまま。
3. **DB の列挙 CHECK を新しい一覧に書き換える** — 絵文字を足すたびに migration＋Stage 分割が要る。`portfolio_reactions` と流儀も揃わない。形式 CHECK に。
4. **基本 5 種を 🤣 込みの 6〜8 種に増やすだけ** — 一番手軽だが「いろんな絵文字を選べる」には足りず、増やすほど吹き出しが横に長くなる（スマホではみ出す）。「＋」の段階構造に。

## 追補（2026-09-26）: 動く絵文字 — Noto Emoji Animation をホバー中と押した直後だけ動かす

### Context

「TikTok みたいに GIF のスタンプでリアクションしたい。ちいかわのスタンプがかわいいので使いたい」という要望があった（2026-09-25）。

- ちいかわ等の既存キャラクターの画像・LINE スタンプは著作物で、社内システムへの複製・配信にも許諾が要る。ファンアートも同じ。**入れない。**
- 「動くリアクション」自体は、権利のはっきりした素材があれば ADR 044 の仕組み（type コードで保存・表示はコード側の定義）の延長で作れる。DB・migration は要らない。

### Decision

1. **素材は Google の Noto Emoji Animation（CC BY 4.0）。** 44 種の拡張パレット＋基本 5 種のうち Noto に素材がある 45 種を、96px のアニメ WebP にして自オリジン `public/img/emoji-anim/<codepoint>.webp` に置く（外部 CDN 依存を作らない・#1166/#1169 の方針どおり）。変換は `scripts/build-emoji-anim.sh`（curl → ffmpeg → img2webp）。素材が無い 🍺 🙇 💦 💤 は静止のまま。帰属表示は `public/img/emoji-anim/LICENSE.md` と `guide-navigation.html` に置く。
2. **常時は動かさない。動くのは「ホバー中」と「自分が押した直後の 2.4 秒」だけ。** タイムラインに並ぶピルが全部動くと CPU・電池・目障りさの三重苦になる。TikTok / Slack も投稿上のリアクションは静止で、動くのはピッカーと押した瞬間。
   - PC: ピッカーのボタンとピルにマウスを乗せると動く（`(hover: hover)` の端末のみ。タッチ端末は mouseover が張り付くので使わない）。
   - 全端末: 自分が押した直後、その種別のピルが 2.4 秒動いて静止に戻る（楽観的更新の直後に `_twEmojiPlayOnceIn`）。
   - OS の「視差効果を減らす」（`prefers-reduced-motion: reduce`）が ON なら一切動かさない。
3. **表示の入れ替えは `<span class="tw-emoji" data-anim="…">🤣</span>` の中身を `<img>` に差し替える方式。** 画像は `onload` 後に差し替えるので初回もチラつかず、読み込みは動かす瞬間まで走らない（ページ表示時の通信量は増えない）。DB の値・通知の文面・作品ギャラリーは変更なし。
4. **オリジナルのスタンプ（自社キャラ）は別途。** 「ちいかわ的なかわいさ」を合法に持ち込む本命はこちらだが、キャラの方向性を決めてから画像づくり → 組み込みの 2 段になるので、今回は Noto の動く絵文字までとする。

### Consequences

- 🤣 🔥 🎉 などを押すと、そのピルがひと呼吸動いてから静止する。PC ではピッカーで絵文字に触れると動く。
- リポジトリに約 4MB（45 ファイル × 約 90KB）のバイナリが増える。以後の追加は `EXTRA_REACTIONS` に 1 行足して `scripts/build-emoji-anim.sh` を 1 回流す。
- `utils/reactions.js` に `emojiCodepoint()` / `REACTION_ANIM_SRC` / `ANIM_UNAVAILABLE` が増える。テストで「定義にある動く絵文字のファイルが実在すること」を守る。

### Alternatives considered

1. **ちいかわ公式素材の利用** — 権利上不可。法人ライセンスも社内ツール用途では現実的でない。
2. **GIPHY / Tenor 連携** — 外部 CDN・API 依存で CDN ゼロ方針に反し、業務システムに出てくる内容を制御できない。
3. **Lottie（JSON）で再生** — 素材は 20〜80KB と軽いが再生用 JS（lottie-web 約 60KB）が要り、`<img>` より実装が重い。WebP に。
4. **タイムラインで常時アニメ** — 見た目は派手だが 1 画面に数十個動くことになり、電池・CPU・集中を削る。ホバー／押した直後だけに。
