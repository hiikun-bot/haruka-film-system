# ADR 041: つぶやきの新着は「割り込まず、気配で気づかせる」（ナビ未読バッジ＋ホームカード）

- Status: Accepted
- Date: 2026-09-16
- Related: ADR 040（ホーム最上段＝マイフォーカス）, ADR 036（マイ実績カード）, ADR 015（VIEW AS チェックリスト）, 通知 Phase 1 段階4（tweets 拡張・`2026-05-03_notification_phase4_tweets_rich.sql`）

## Context

「つぶやかれたら、ログイン中の全員にポップアップで見せたい。HARUKA FILM のシステムを愛してもらえるよう、巡回したくなる仕掛けが欲しい」という要望があった（2026-09-16）。

現状の確認結果:

| 項目 | 実装状況 |
|---|---|
| つぶやき投稿時の通知 | メンションされた人にだけ `mention` 通知。それ以外の人には何も届かない |
| 通知の見せ方 | ベルのバッジ +1 と点滅のみ。トーストもモーダルも無い |
| Realtime | `tweets` は `supabase_realtime` publication 登録済み・RLS 無し。ブラウザは `notification_logs` の INSERT だけ購読している |
| ホーム | 数字（ヒーロー）と自分の手番（ADR 040）のみ。人の気配が乗るカードは無い |

編集者・デザイナーは Premiere / Photoshop から HFS に切り替えて作業する。自分宛てでない話題が作業中に画面を塞ぐと「閉じる」が反射動作になり、愛着どころか嫌悪に転じるリスクが高い。狙いは「通知」ではなく「開いたら仲間の気配がある」状態を作ることである。

## Decision

1. **強制ポップアップ／モーダルは採用しない。** トーストも今回は出さない（出すなら本人が ON/OFF できる通知設定付きで、別 ADR）。
2. **ナビ「つぶやき」に未読バッジを付ける。** 数えるのは「最終閲覧以降の、他人の、期限内（またはピン留め）の投稿数」。自分の投稿は数えない。
3. **最終閲覧時刻はブラウザの localStorage に持つ（`hfs_tweets_seen_at`）。サーバーには保存しない。**
   - migration 不要で 1 PR に収まること、「読んだ」の粒度が端末単位で十分なことが理由。
   - 端末が変わったときの起点は 24 時間前（`utils/tweets-unread.js` の既定）。30 日より前は 30 日前に丸め、久しぶりに開いた人に 200 件の赤バッジを出さない。
   - 端末間で既読を同期したくなったら `users` に列を足す（別 ADR）。
4. **「みんなのつぶやき」タブを読み込めた時点で既読にする。** `mine` タブは他人の新着を見ていないので触らない。
5. **ホームのマイフォーカス直下に「💭 みんなのつぶやき」カード（最新 3 件・`order=recent`）を置く。** ピン留めを優先しない（3 枠が常にピンで埋まり「いま何が起きているか」が見えなくなるため）。「新着 N 件」チップはナビのバッジと同じ数。「＋ つぶやく」「すべて見る →」を添える。
6. **新着の検知は既存の Realtime チャネルに `tweets` INSERT の購読を足す**（`notification-realtime.js` → CustomEvent `tweets:incoming`）。受信側は本文を使わず、サーバーから件数・カードを取り直す。切断中の取りこぼしは `visibilitychange`・SUBSCRIBED 復帰・10 分間隔の再取得で補う。
7. **つぶやきページを開いている最中の新着は一覧を勝手に入れ替えない。** 先頭に「🆕 新しいつぶやきが N 件あります」バーを出し、タップで再読込（入力中の返信を消さないため）。
8. **`?tweet=<id>` 深リンクを実装する。** メンション通知の `link_url` は以前からこの形式だったが `applyDeepLinkOnLoad()` に受け口が無く、ホームに落ちていた。ホームカード・通知パネル・深リンクの 3 経路とも `openTweetsPage(id)` → 該当カードへスクロール＋ハイライトに統一する。
9. **ロール分岐を書かない。** 全員が同じつぶやきを見るので VIEW AS で表示は変わらない（ADR 015 上の権限漏れではない）。

## Consequences

- API: `GET /api/haruka/tweets` に `limit`（1〜200）と `order=recent` を追加。`GET /api/haruka/tweets/unread-count?since=<ISO>` を新設（HEAD + exact count、`idx_tweets_active` が効く）。
- 端末ごとに既読が独立するため、PC で読んだつぶやきがスマホでは未読のまま出ることがある（24 時間分まで）。許容する。
- Realtime の `tweets` INSERT は全員に届く（RLS 無しのため）。本文はイベントから読まず、表示は認証付き API から取り直すので情報の露出は現状と変わらない。
- 次の段階（本 ADR の範囲外）: 本人が ON/OFF できる右下トースト、既読の端末間同期、つぶやきページ内での自動差し込み。
