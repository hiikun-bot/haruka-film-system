# ADR 050: 投稿前チェック — Premiere の中で、書き出す前に「前に指摘されたこと」に気づけるようにする

- Status: Proposed
- Date: 2026-10-11
- Related: ADR 039（Gemini / Vertex AI の使い方と予算ガード）, 旧 `HARUKA-FILM-SYSTEM/premiere`（2026-04 の UXP 雛形。古いので使わない・さとるさん判断）

## Context

ひげごろー様の切り抜きショート動画では、先方からの指摘を「投稿前チェックリスト」シート（スケジュール管理表の 1 タブ）に積み上げてきた（2026-10-11 時点で 57 件）。同じ指摘が繰り返されるのは、編集者が書き出して提出したあとに初めて指摘が届くから。さとるさんの方針（2026-10-11）:

- **書き出す前に、Premiere の中で編集者が気づける**こと
- 指摘は今後も増え続ける。**シートに書き足せば、ツールの入れ直しなしで効く**こと
- Mac・Windows 両対応。編集者は HARUKA FILM のメンバー全員
- Premiere Pro 2026（v26）で作る

## Decision

### 1. 三層に分ける。ルールはシート、判断はサーバー、パネルは「目と手」だけ

```
 正本: 案件ごとのシート（ひげごろー = 投稿前チェックリスト）
        │ サーバーがサービスアカウントで読む（1 分キャッシュ）
        ▼
 判定: HARUKA FILM SYSTEM  POST /api/precheck/check
        辞書・必須はサーバーで照合／AI は Gemini（ADR 039 と同じ Vertex AI）
        ▼ 結果だけ返す
 表示: Premiere UXP パネル（plugins/premiere-precheck）
        テロップを読んで送る・結果の一覧・[移動]・タイムラインにマーカー
```

パネルに判定ロジックを持たせないので、ルールの追加・判定の改善はサーバーのデプロイだけで全員に届く。パネルの入れ直しが要るのは「Premiere から新しい種類のデータを読みたい」ときだけ。

### 2. ルールはシートの 1 行 = 1 ルール。判定方法は F 列のプルダウンで決める

列: A No / B 対象ファイル / C 項目 / D 指摘内容 / E 備考 / F 判定方法 / G 誤 / H 正

| 判定方法 | どこで判定するか | 結果の強さ |
|---|---|---|
| 辞書 | サーバーで文字を照合。G と H は「／」区切りで同じ順に対応。H が「（削除）」なら消す指示 | ✕（直さないと提出できない） |
| 必須 | キャプション文が渡されたときだけ AI が有無を判定 | △ |
| AI | 指摘内容の文章をそのまま Gemini に渡し、テロップ全体・文字起こし・分野と突き合わせる | △（最後は編集者が判断） |
| 映像 | 自動判定は準備中。パネルに確認欄（□）を出す | □ |
| 人 | パネルに確認欄（□）を出すだけ | □ |
| 空欄 | AI として扱う（書き足した人が判定方法を選び忘れても効く） | △ |

### 3. 「何の動画か」は管理番号で引く

シーケンス名に含まれる管理番号（例 `K-001-1`）で「投稿予定一覧」タブを引き、区分・等級・試験区分・大中小分類を AI に渡す。No.3/10/17/27/28 のように **正しい科目名が動画の分類で変わる** 指摘があるため（辞書にできない）。

### 4. パネルの認証はメンバーごとの「プラグイン用トークン」

HARUKA FILM SYSTEM はブラウザのセッション Cookie で認証しているが、UXP パネルからは使えない。メンバーは `/premiere-plugin.html`（ログイン必須）で自分用のトークンを発行し、パネルに貼る。

- 形式: `hfpc1.<user_id>.<発行unix秒>.<署名>`。署名は `SESSION_SECRET` から用途別に派生した鍵の HMAC-SHA256
- 検証のたびに `users.is_active` を見る（退任したメンバーはその場で使えなくなる）。有効期限 180 日
- **DB テーブルは作らない**（MVP）。個別失効が必要になったら `precheck_tokens` テーブルへ移す

### 5. AI は Gemini（ADR 039 と同じ Vertex AI・サービスアカウント）。モデルは環境変数で替える

`PRECHECK_MODEL`（未設定なら `GEMINI_MODEL`、それも無ければ `gemini-3.8-flash`）。費用は 1 回あたり数円の見立て。モデル選定は、過去の指摘から作る答え付きの問題で精度を比べて決める（別 PR）。

### 6. パネルは UXP（Premiere 26.0 以上）

UXP は Premiere 25.6 で正式提供、CEP は 2029 年末に廃止予定（Adobe 2026-09 発表）。テロップは各ビデオトラックのクリップのコンポーネントを辿り、文字の値（`ComponentParam.getValueAtTime`）を読む。**エッセンシャルグラフィックスの値の形は Premiere 上で確かめるまで確定しない** ため、パネルに「診断データを書き出す」を付け、実機で 1 回押してもらって読み取り方を固める。

## Consequences

- 先方の指摘が 1 行増えるたびに、次のチェックから全員に効く
- 辞書の照合は誤検知が少なく即時。AI の判定は △ に留め、編集者の判断を奪わない
- 判定ログは MVP では持たない（サーバーログのみ）。「機械が見逃して先方に指摘されたもの」の洗い出しは次段階で DB に記録する

## Alternatives

- **パネルに判定ロジックを持たせる**: ルール追加のたびに全員がプラグインを入れ直すことになる。不採用
- **書き出した mp4 だけを見る**: 編集者が気づくのが書き出し後になり、目的（書き出す前に気づく）に合わない。映像でしか分からない項目（白い画面・コメント欄の名前）の確認用に、後段で追加する
- **ひげごろー側のサーバー（track.higegoro.tech）に置く**: メンバーの認証と AI の契約を新しく用意する必要がある。使う人が HARUKA FILM のメンバーなので不採用（さとるさん判断 2026-10-11）
