# ADR 052: 🎞 思い出アルバムは DB を持たず、共有ドライブの「アルバム/投稿者」フォルダにブラウザから直送する

- Status: Accepted
- Date: 2026-10-26
- Related: ADR 015（VIEW AS チェックリスト）, ADR 048（新テーブルは RLS 必須 → 本件はテーブルを作らない）

## Context

淡路島合宿（2026-10）のあと、参加メンバーから「撮った写真・動画をどう共有するか」の相談があった（Chatwork 淡路島参加チャット・2026-10-26）。

- LINE アルバムは LYP プレミアムでないと動画を入れられず、一度に送れる本数にも上限がある
- Google ドライブの共有アカウントを使ってよいのか分からない
- 「HF システムに入れられるならめちゃいい」

さとるさんの指示: ファイル名は変えなくてよい。まずは **アップロードしやすく・整理しやすく**、**無料の範囲で**。

## Decision

### 1. 保存先は既存の Drive 連携（共有ドライブ）。DB テーブルは作らない

`<Drive ルート>/🎞 思い出アルバム/<アルバム名>/<投稿者名>/<元のファイル名>`

- アルバム = 「🎞 思い出アルバム」直下のフォルダ（`appProperties.hfs_kind='memories_album'`）
- 投稿者 = アルバム直下のフォルダ（`appProperties.hfs_uploader_id=users.id`。表示名が同じ人がいても ID で区別。名前はニックネーム→氏名）
- ファイル = 元のファイル名のまま。`appProperties.hfs_uploader_id` と `hfs_taken_at`（ブラウザの lastModified）を付ける
- 一覧は Drive の files.list をそのまま読む（30 秒キャッシュ・アップロード／削除で破棄）。Drive に直接入れたファイルも、投稿者フォルダから投稿者を補って表示する

DB を持たないのは、(a) 1 イベントの写真置き場に migration → 適用 → コードの 3 段を踏む価値が薄い、(b) Drive が正なので二重管理のズレが起きない、(c) 「Drive で開く」から Drive の UI で一括ダウンロードもできる、ため。

### 2. アップロードはクリエイティブと同じ「ブラウザ → Drive の Resumable 直送」

バイトは Railway を通さない（約 5 分のエッジ timeout で 502 になる問題・`project_railway_upload_502`）。haruka.html の共通コア `driveUploadToSession()`（受領位置再開・チャンク縮小・停止検知・読取診断）を使う。同時 2 ファイル・1 ファイル 10GB まで。写真・動画以外（拡張子と mime で判定）は受け付けない。

### 3. 並びは撮影日（JST）ごと。撮影日時は EXIF → lastModified → Drive 作成日時

写真は Drive が読む EXIF 時刻（カメラのローカル時刻＝JST とみなす）、動画は EXIF が取れないのでアップロード時の lastModified、どちらも無ければ Drive の作成日時。画面ではこの日付で見出しを切り、投稿者チップ・写真/動画チップで絞り込む。

### 4. 閲覧・保存

- サムネはサーバーが Drive の thumbnailLink を代理配信（短命 URL を隠す）。「思い出アルバム配下のファイルか」を親フォルダを辿って確かめてから返す
- 写真はライトボックスで大きく、動画は Drive のプレーヤー（`/file/d/<id>/preview`）で再生
- ファイル・アルバムフォルダには「リンクを知っている人は閲覧可」を付ける（クリエイティブ・素材広場と同じ運用）。URL は画面内にしか出さない

### 5. 権限

- 閲覧・アップロード: ログイン中の全員（requireAuth のみ。permission key は作らない）
- アルバム作成: admin（実効ロール・`requireRole('admin')`）。アルバムが 1 つも無いときは「淡路島合宿 2026」を自動で作る
- 削除: 投稿した本人（`req.user.id` と `hfs_uploader_id` の一致・VIEW AS の影響なし）か admin（実効ロール）。共有ドライブは SA が完全削除できないのでゴミ箱送り

## Consequences

- 追加の費用は無い。ただし保存容量は Google Workspace の組織全体の容量を使う。動画が大量に増えて上限に近づいたら、プラン変更（有料）の前に必ず相談する
- 通知・つぶやきへの自動投稿はしない（1 人 1 通の原則・ADR 049 / フィードバック「まとめて1回」。必要なら後でまとめ通知を足す）
- いいね・コメントは持たない（必要になったら別 ADR。作品ギャラリーの ADR 042 とは混ぜない）
- iPhone の写真ライブラリから選ぶと、Safari の設定によって HEIC が JPEG に変換されて届く（ファイル名の拡張子が変わることがある）

## Alternatives

- **LINE アルバム**: 動画が有料・本数制限。却下
- **Cloudflare R2**: 無料枠 10GB は動画ですぐ超える（perf 第 2 弾で「10GB 厳守」と決めている）。却下
- **Supabase Storage**: 無料枠 1GB。却下
- **DB にメタデータを持つ（memories / memory_items テーブル）**: いいね・コメント・アルバム権限など拡張には向くが、今回は不要。必要になった時点で Drive の appProperties から移行できる
