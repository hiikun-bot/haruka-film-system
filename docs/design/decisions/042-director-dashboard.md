# ADR 042: ディレクターのホームは「自分の手番＋自チームで止まっているもの」で構成し、人単位の負荷は出さない

- Status: Accepted
- Date: 2026-09-16
- Related: ADR 033（チーム状況＝人単位の負荷は admin＋P層限定）, ADR 040（マイフォーカス／その追補）, ADR 036（マイ実績）, ADR 016（ボール状態）, ADR 015（VIEW AS チェックリスト）

## Context

`renderDirectorDash()` は「ディレクターは自チームに絞ったアラート＋全体俯瞰」というコメントを持ちながら、
実体は `renderAdminDash(today)` を呼ぶだけだった。結果としてディレクターのホームには
**会社全体**の売上予実・クリエイティブステータス構成比・案件ステータス構成比・月別納品本数・
全社の納期アラート・年月フィルタが並び、自分やチームの管理には使えない状態だった
（ADR 040 の Consequences で Phase 3 の宿題として明記していた）。

ディレクターが日々知りたいのは次の 2 つである。

1. **自分の手番**（Dチェック待ちなど）→ ADR 040 のマイフォーカスで既に解決済み
2. **自チームで止まっているもの**（SOS・納期超過・今週締切）→ 置き場所が無い

ここで設計上の論点がある。ADR 033（チーム状況）は「誰にどれくらい仕事が乗っているか」の
**人単位の負荷集計**を admin＋プロデューサー層に限定し、**director 単独は `team_load.page` = false** と決めた。
理由は「メンバー同士の比較・詮索の材料にしない」こと。
一方でディレクターは自チームの進行に責任を持つため、何も見えないのも困る。

## Decision

1. **`renderDirectorDash()` は `renderAdminDash()` の流用をやめ、独立実装にする。**
   ディレクターのホームから会社全体のグラフ（売上予実 / ステータス構成比 / 月別納品本数）・
   予実テーブル・全社の納期アラート・年月フィルタを外す。
   構成は 🎯 マイフォーカス（ADR 040）＋ 👥 自チームで気になるもの（本 ADR）の 2 枚。
   ステータス構成比や売上を見たい場合は分析タブ（`analytics.view`）を使う。
2. **「👥 自チームで気になるもの」は CR 単位のリストだけを返す。人単位の集計・順位・負荷スコアは返さない。**
   ADR 033 の線を越えないための中心的な判断。画面が答えるのは
   **「どの制作物が止まっているか」**であって**「誰が何件抱えているか」**ではない。
   行には「いま誰で止まっているか」（ボール保持者 1 名またはクライアント等のラベル）が出るが、
   これは次に動かす人を示す動線であり、人ごとの件数集計・並べ替え・比較 UI は作らない。
   人単位の負荷が必要になった場合は ADR 033 を改訂して `team_load.page` を director に開くのが筋で、
   本 ADR のカードを人単位表示に拡張してはならない。
3. **「自チーム」の範囲と「気になる」の定義（JST 固定）。**

   | 用語 | 定義 |
   |---|---|
   | 自チーム範囲 | 未納品CRのうち、**自分が案件の `director_id` / `producer_id`**（経路 b）、または **自分が代表ディレクターのチームのメンバーが担当**（経路 c）のもの。自分の `creative_assignments`（経路 a）は「自分の作業」なので対象外 |
   | 気になる | SOS（`help_flag`）が立っている／`final_deadline` < 今日（JST）／`final_deadline` が今日〜今週日曜（JST） のいずれか。どれにも当てはまらない CR は件数にも出さない |
   | 除外 | **自分にボールがある CR**（🎯 マイフォーカスに出ているため。ホーム内で二重に出さない） |
   | 並び順 | SOS → 期限超過（古い順）→ 今週締切（近い順）。同着はファイル名 |

   クライアント確認待ちは「制作の手は止まっているがボールは外」だが、納期は生きているため
   超過していれば対象にする（催促の起点になる）。
4. **API は `GET /dashboard/my-focus` のレスポンスに `team` を足す形にする。** 新エンドポイントは作らない。
   候補CRの 3 経路は Phase 1 で既に取得済みで、そこに `in_team_scope` フラグを立てるだけで足りるため。
   `team.enabled` は **CR の件数ではなく「自分が案件 D/P か、チーム代表ディレクターか」** で決める
   （0 件でもカードを出して「気になるものはありません ✓」を見せる）。
   フロントは `team.enabled` を見るだけで、**ロール分岐は書かない**（admin / プロデューサーが
   案件 D/P を持っていればそのまま同じカードが出る）。
5. **名前の表示は `NameDisplay` 経由に統一する。**
   API は `ball_holder_user = { id, full_name, nickname }` を返し、整形はフロントで行う。
   users が解決できないボール（クライアント等）は `ball_holder_label` の文字列だけを返す。
6. **年月フィルタ（`#dash-filter`）はグラフ・予実を出すロール（admin / secretary / producer / producer_director）だけに表示する。**
   従来は全ロールに出ており、グラフの無い作り手・ディレクターにも意味のないセレクトが見えていた。

## Consequences

- ディレクターのホームが「自分の手番」と「チームで止まっているもの」だけになり、毎日見る意味のある画面になる。
- ディレクターは会社全体の売上・構成比をホームでは見られなくなる。必要なら分析タブへ（権限は従来どおり）。
- 人単位の負荷（誰が何件）は引き続き admin＋プロデューサー層の「📊 チーム状況」でのみ見られる。ADR 033 の意図は保たれる。
- `team` は同じ API で返るため、admin / プロデューサーが案件 D/P を持っていれば同じカードが出る。
  ディレクター専用 UI にはしない（ロール分岐をフロントに増やさないため）。
- 新テーブル・migration・permission key の追加は無い。
- 実データ確認（2026-09-16）で、自チームの「期限超過」が 13〜35 件出るディレクターが複数いた。
  その多くが「クライアントチェック中のまま納期を過ぎた」CR であり、納期の更新運用が
  追いついていない可能性がある。カードの定義の問題ではなく運用側の課題として切り分ける。

## Alternatives considered

- **A. ADR 033 を改訂し、ディレクターにも人単位の負荷（チーム状況）を開く**: 「誰が何件」を出すのは
  ADR 033 が明示的に退けた方向で、判断を覆すにはユーザーの意思決定が要る。まず CR 単位で必要十分か
  運用して確かめる。必要になれば ADR 033 側を改訂する（本 ADR のカードを拡張するのではなく）。
- **B. 専用エンドポイント `GET /dashboard/my-team-focus` を作る**: 候補CRの取得が my-focus と完全に重複し、
  ホームで 2 本叩くことになる。同一レスポンスに相乗りさせた。
- **C. 「3日以上ステータスが動いていないCR」を出す**: 最も知りたい指標だが、`creative_status_audit` は
  本番 DB に存在せず（silent skip 状態）、`updated_at` はステータス以外の編集でも動くため代用できない。
  ステータス遷移履歴が取れるようになってから別途検討する。
- **D. ディレクターにも全社グラフを残す**: 「自チームに絞る」という当初の意図と矛盾し、
  ホームが縦に長くなるだけで行動につながらない。分析タブに役割を渡す。
